# Learning collection

The workspace has a left column grouping explored repository maps and saved learning paths by repository. Selecting a path restores it; selecting a repository reopens its existing workflow map, or pre-fills its URL when that map has expired. The previous path dropdown is replaced by the collection. A search narrows repositories and path titles. Mobile uses a collapsible collection above the workspace.

Right-click an item, press Shift+F10/the context-menu key, or use its visible three-dot button. Actions open a path/workflow map, view the public GitHub repository, or remove the selected item. Menus support arrow keys, Home/End, Escape and standard Tab navigation. Help explains record retention and deletion boundaries.

An in-page modal confirmation defaults focus to Cancel, traps focus through the native dialog, supports Escape, and restores focus on cancellation. Removing requires a separate explicit Remove click; browser confirmation auto-accept behavior cannot remove records. While removal is pending, both controls are disabled and duplicate requests are blocked. Removing a path asks for explicit confirmation and deletes only that path's saved evidence. Removing a repository asks for confirmation with its path count, then deletes its maps and saved paths for the authenticated user and current pilot only. The backend uses a single database batch with the existing foreign-key cascade. GitHub repositories and independent local caches, working copies and backups are retained. An ended/deleted active attempt no longer blocks model use. Existing capacity/availability limits remain: six maps for 24 hours and six saved paths for 30 days.
